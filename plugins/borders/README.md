# Background Progress

Borders provides a window-scoped background-task presentation API at `BordersApi.progress`. It does not execute commands, start network requests, or own cancellation of business operations. Consumers use the existing per-App service registry; never access installed plugin instances or footer DOM.

## Contract

Types are defined in `plugins/contracts/progress.ts`. Feature-detect `borders?.progress` because older Borders providers do not expose this capability.

| API | Behavior |
| --- | --- |
| `progress.start(options)` | Returns a task handle. Requires an owner, a nonblank title and a valid `CallContext` for a window with a footer. |
| `handle.update({ title, details, fraction })` | Updates only supplied fields. `fraction: null` selects continuous animation; a finite number from 0 to 1 selects determinate progress. Zero is valid determinate progress. |
| `handle.cancel()` | Requests cancellation once through `onCancel`, when available. The task remains visible as `Stopping…` until the consumer finishes it. |
| `handle.finish()` / `handle.dispose()` | Idempotently removes presentation and releases its timer and signal listener. Does not cancel work. |
| `progress.getTasks(context)` | Returns immutable snapshots for that window, including tasks awaiting the display delay. |
| `progress.subscribe(context, listener)` | Immediately delivers a snapshot, then updates. Returns an unsubscribe function. |

`ProgressOptions` accepts `owner`, `title`, `context`, optional `details`, optional `fraction`, and optional `onCancel`. Task IDs are generated by the provider; callers must not reuse IDs across provider lifetimes. Snapshots contain plain data only, including `visible`, `state`, `cancellable`, and an optional `cancellationError`.

The optional `context.signal` controls the presentation lifetime. Aborting it removes the task without invoking `onCancel`. Use a plugin-lifetime signal or explicitly dispose all handles when the consuming module unloads. Keep business-operation cancellation separate.

## Consumer Example

```ts
import type { ModuleId } from "../../contracts/common";
import { getServiceRegistry } from "../../utils/service-registry";
import { getWindowContext } from "../../utils/windows";

// Create once during consumer load, and abort during consumer unload.
const presentationLifetime = new AbortController();
plugin.register(() => presentationLifetime.abort());

async function runWithProgress(
    owner: ModuleId,
    document: Document,
    title: string,
    operation: (signal: AbortSignal) => Promise<void>,
) {
    const progress = getServiceRegistry(plugin.app).get("borders")?.progress;
    if (!progress) throw new Error("Background progress is unavailable.");

    const execution = new AbortController();
    const task = progress.start({
        owner,
        title,
        context: { ...getWindowContext(document), signal: presentationLifetime.signal },
        onCancel: () => execution.abort(),
    });
    try {
        await operation(execution.signal);
    } finally {
        task.finish();
    }
}
```

The caller decides how to report success and failure. It must connect cancellation to its actual operation and always finish the handle in `finally`. Resolving `onCancel` acknowledges the request; it does not mean the operation has stopped. A rejected callback leaves the task running, exposes a generic retry message, and enables another cancellation request.

Subscribe through `getServiceRegistry(app).watch(owner, "borders", ...)` when maintaining long-lived integration. A provider replacement invalidates old handles: updates become harmless no-ops, and new calls through the retired API fail. If an operation continues across replacement, register a new task with the new provider using caller-owned state. Borders never restarts or cancels that operation.

## Presentation and Lifetime

- Tasks lasting less than 200 ms do not flash in the footer.
- The compact footer shows the oldest visible task, a 104 px by 4 px progress bar, an optional cancellation button, and a count for multiple tasks.
- Indeterminate progress uses a continuous 800 ms blue gradient animation. Progress updates are coalesced into animation frames without recreating controls.
- Clicking the summary opens a non-modal task list with titles, details, progress, and per-task cancellation. Escape, the top-right minus button, or outside interaction minimizes the list without stopping tasks. The X beside each progress track requests cancellation only when the caller registered onCancel.
- Drag the task-list header to move it, or drag any edge/corner to change its width and height. The bottom-right resize handle also accepts arrow keys. Geometry stays inside the viewport and is retained when reopening in the same window until Borders unloads. Resized task lists scroll internally; updates do not reset user geometry. Closing the popup releases pointer capture, listeners and scheduled geometry updates.
- Determinate progress exposes an accessible numeric value. Indeterminate progress has no fabricated percentage. Reduced-motion preferences disable continuous movement.
- Each window owns its own footer and tasks. Invalid or unsupported window contexts fail explicitly; tasks never move to another window automatically.
- Completing a task removes only that task. The footer hides after the last visible task finishes.
- Closing a window, aborting the presentation signal, or unloading Borders releases corresponding presentation state, listeners, animation frames, and popup nodes without cancelling business work.

Git and other feature integrations are separate consumer work. This feature contains no Git command execution or automatic Git integration.
